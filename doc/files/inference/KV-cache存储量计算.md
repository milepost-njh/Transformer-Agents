## 1.2 单个token的KV Cache计算

### 1.2.1 不同注意力机制的KV Cache计算公式
- **MHA (Multi-Head Attention):** `KV Cache = 层数 × 注意力头数 × 头维度 × 2(K和V)`
- **MQA (Multi-Query Attention):** `KV Cache = 层数 × 头维度 × 2(K和V)`
- **MLA (Multi-head Latent Attention):** `KV Cache = 层数 × (4 × 头维度 + 头维度 / 2)` (每个Transformer层缓存 c_t^KV 和 k_t^R)

### 1.2.2 具体数值

**你的模型 (MHA):**
```
8层 × 8个Head × 64维度 × 2(K和V) = 8,192个参数
```

**你的模型 (MQA):**
```
8层 × 64维度 × 2(K和V) = 1,024个参数
```

**你的模型 (MLA):**
```
8层 × (4 × 64维度 + 64维度 / 2) = 8层 × (256 + 32)维度 = 8层 × 288维度 = 2,304个参数
```

**Qwen-72B (MHA):**
```
80层 × 64个Head × 128维度 × 2(K和V) = 1,310,720个参数
```

### 1.2.3 GPU显存占用

假设使用bf16精度（2字节/参数）：

**你的模型 (MHA):**
```
8,192个参数 × 2字节 = 16,384字节 = 16KB
```

**你的模型 (MQA):**
```
1,024个参数 × 2字节 = 2,048字节 = 2KB
```

**你的模型 (MLA):**
```
2,304个参数 × 2字节 = 4,608字节 = 4.5KB
```

**Qwen-72B (MHA):**
```
1,310,720个参数 × 2字节 = 2,621,440字节 = 2.62MB
```

## 1.6 MLA-KV-cache推理报告

### 1.6.1 实验结果（64 tokens）

**测试命令**:
```shell
CUDA_VISIBLE_DEVICES=1 python inference/compare_kv_cache_mla.py \
    --mla_checkpoint checkpoints/mid_e1_s222.pt \
    --no_mla_checkpoint checkpoints_no_mla/mid_e1_s222.pt \
    --test_lengths 64
```

**对比结果**:
| 指标 | MLA | Standard | 差异 |
|------|-----|----------|------|
| KV-cache显存 | 0.66 MB | 1.00 MB | 节省 34.0% |
| 推理时间 | 2.667s | 2.344s | 慢 13.8% |
| 总GPU显存 | 1657 MB | 1689 MB | -32 MB |

**结论**: ✅ MLA节省 34.0% KV-cache显存，但推理慢 13.8%

### 1.6.2 理论验证

**模型配置**: 8层, 8头, head_dim=64, d_model=512, bf16精度

**KV-cache计算**:
```
Standard: 2 × 8头 × 64 × 8层 × 64tokens × 2bytes = 1.00 MB
MLA:      (128 + 32 + 512) × 8层 × 64tokens × 2bytes = 0.66 MB
压缩比:   34.0% ✅
```

#### 关键发现

1. **显存节省效果显著**
   - MLA 在 64 tokens 场景下节省 **34.0%** 的 KV-cache 显存
   - 理论计算与实验结果完全吻合，验证了实现的正确性
   - 压缩比在不同序列长度下保持稳定

2. **性能权衡分析**
   - MLA 推理速度慢 **13.8%**（41.61ms vs 36.57ms）
   - 速度损失主要来自额外的低秩投影计算：
     - `q_a_proj` + `q_a_layernorm` + `q_b_proj`
     - `kv_a_proj` + `kv_a_layernorm` + `kv_b_proj`
   - 在长序列或大batch场景下，显存节省带来的收益会超过速度损失

3. **MLA 公式修正**
   - 原文档公式: `8层 × (4 × 64 + 32) = 2,304 参数` (简化版)
   - 实际实现: `8层 × (128 + 32 + 512) = 5,376 参数` (完整版)
   - 使用 bf16 精度 (2 bytes/参数)，与文档前面的计算保持一致

4. **适用场景**
   - ✅ **长序列推理**: 序列越长，显存节省越显著
   - ✅ **大batch推理**: batch size 越大，显存优势越明显
   - ✅ **显存受限环境**: 可以在相同显存下支持更长序列
   - ⚠️ **实时推理**: 单步延迟增加 13.8%，需权衡

#### 实现要点

1. **KV-cache 机制**
   - 实现了真正的增量式 KV 缓存
   - 每步只计算新 token 的 K/V，与历史缓存拼接
   - 支持标准注意力和 MLA 两种模式

2. **显存追踪**
   - 使用 `torch.cuda.memory_allocated()` 实时监控
   - 理论计算与实际测量相互验证
   - 提供详细的显存分解分析

3. **代码位置**
   - KV-cache 实现: `train_tmp.py` 第759-916行
   - 测试脚本: `inference/compare_kv_cache_mla.py`
   - 文档: `inference/README_KV_CACHE.md`
